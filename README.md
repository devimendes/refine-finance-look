# Polished Finance

MELHORIA VISUAL COMPLETA DO SISTEMA — PRESERVAR 100% DAS FUNCIONALIDADES

Quero realizar uma melhoria profissional, consistente e moderna na interface visual e no layout do sistema financeiro atual.

REGRA MAIS IMPORTANTE

NÃO ALTERE, REMOVA, REESCREVA, SIMPLIFIQUE OU SUBSTITUA NENHUMA FUNCIONALIDADE EXISTENTE.

Esta tarefa é exclusivamente de UI/UX, design visual, organização espacial, hierarquia visual, responsividade e usabilidade.

O sistema já possui funcionalidades implementadas e funcionando. A prioridade absoluta é preservar o comportamento atual.

Antes de qualquer alteração

Analise cuidadosamente toda a aplicação existente.

Identifique a estrutura atual das páginas, componentes, menus, formulários, tabelas, cards, modais, filtros, gráficos e botões.

Identifique quais elementos são apenas visuais e quais possuem lógica funcional associada.

Não altere a lógica de negócio para solucionar problemas visuais.

Não altere nomes de campos, IDs, estruturas de dados, eventos, funções, cálculos ou regras existentes apenas para melhorar a aparência.

Não substitua componentes funcionais por versões simplificadas.

Não remova funcionalidades que pareçam redundantes.

Não crie funcionalidades novas nesta etapa.

OBJETIVO DO REDESIGN

Transformar a interface atual em uma aplicação financeira:

moderna;

profissional;

elegante;

limpa;

intuitiva;

visualmente organizada;

confortável para uso diário;

com aparência de software financeiro profissional;

com excelente hierarquia visual;

com excelente experiência em desktop;

responsiva para telas menores.

O redesign deve transmitir controle, organização, confiança e profissionalismo, sem deixar a interface excessivamente decorada.

DIREÇÃO VISUAL

Adote uma estética:

Clean + Premium + Financeiro + Profissional

Priorize:

espaços em branco;

alinhamento consistente;

tipografia profissional;

hierarquia visual clara;

cards discretos;

bordas suaves;

sombras muito sutis;

ícones consistentes;

elementos visualmente equilibrados;

baixo nível de poluição visual.

Evite:

excesso de cores;

gradientes exagerados;

efeitos chamativos;

sombras fortes;

excesso de bordas;

elementos gigantes;

animações desnecessárias;

aparência de template genérico;

visual excessivamente "colorido".

1. SISTEMA DE DESIGN

Crie ou organize um sistema visual consistente para toda a aplicação.

Defina tokens reutilizáveis para:

cores;

tipografia;

espaçamentos;

raios de borda;

sombras;

tamanhos de ícones;

altura dos controles;

estados de interação.

Todos os componentes devem utilizar esse mesmo sistema.

Evite estilos diferentes para componentes que possuem a mesma finalidade.

2. TIPOGRAFIA

Melhore a hierarquia tipográfica.

Utilize níveis claros para:

título da página;

subtítulo;

títulos de seção;

títulos de cards;

valores financeiros;

labels;

textos auxiliares;

tabelas;

mensagens de sistema.

Os valores financeiros importantes devem possuir maior destaque visual.

Não utilize tamanhos exagerados.

Priorize legibilidade.

3. MENU LATERAL / NAVEGAÇÃO

Melhore visualmente a navegação existente sem alterar nenhuma rota ou funcionalidade.

O menu deve apresentar:

hierarquia clara;

ícones consistentes;

espaçamento confortável;

estado ativo claramente identificável;

estados hover;

separação visual adequada entre grupos;

boa leitura dos nomes;

aparência profissional.

Se houver submenus, melhorar sua organização visual.

Não alterar a estrutura funcional da navegação.

Não remover itens existentes.

Não renomear funcionalidades existentes sem necessidade.

4. CABEÇALHO

Melhore o cabeçalho das páginas.

Criar uma hierarquia visual clara entre:

título;

descrição;

filtros;

período;

ações principais.

Os controles de período, filtros e ações devem ficar visualmente organizados.

Evitar que muitos botões tenham o mesmo peso visual.

Utilizar corretamente:

ação primária;

ações secundárias;

ações discretas.

5. DASHBOARD

O dashboard deve receber atenção especial.

Melhorar a apresentação dos indicadores existentes.

Os cards financeiros devem apresentar:

título;

valor;

indicador;

informação complementar, quando já existente;

ícone quando apropriado;

espaçamento adequado.

Criar uma hierarquia clara entre:

informação principal → informação secundária → detalhes.

Não alterar os cálculos dos indicadores.

Não alterar a origem dos dados.

Não alterar filtros ou regras do dashboard.

Apenas melhorar sua apresentação.

6. CARDS

Padronizar todos os cards existentes.

Todos devem seguir uma linguagem visual consistente.

Aplicar:

padding equilibrado;

border-radius consistente;

bordas discretas;

sombra suave;

títulos bem posicionados;

valores bem destacados;

alinhamento consistente.

Evitar cards excessivamente altos.

Evitar excesso de elementos dentro de um mesmo card.

7. TABELAS

Melhorar visualmente todas as tabelas existentes.

Priorizar:

cabeçalhos bem definidos;

alinhamento correto;

espaçamento entre linhas;

leitura fácil dos valores;

separação visual discreta;

hover nas linhas;

destaque para status;

ações organizadas.

Valores monetários devem ficar alinhados de maneira consistente.

Datas devem seguir um padrão visual consistente.

Status como:

pago;

pendente;

vencido;

recebido;

ativo;

inativo;

devem possuir apresentação visual clara.

Não alterar a lógica das tabelas.

8. FORMULÁRIOS

Padronizar visualmente todos os formulários existentes.

Melhorar:

labels;

inputs;

selects;

checkboxes;

radio buttons;

switches;

campos de data;

campos monetários;

mensagens de validação.

Os campos devem possuir:

altura consistente;

bordas discretas;

foco claramente visível;

espaçamento adequado;

labels legíveis.

Não alterar:

nomes dos campos;

validações;

regras;

eventos;

armazenamento;

cálculos.

9. BOTÕES

Criar uma hierarquia visual consistente.

Categorias:

Primário

Para ações principais.

Secundário

Para ações complementares.

Ghost/Discreto

Para ações de menor importância.

Perigoso

Para ações destrutivas ou de risco.

Os botões devem possuir:

tamanho consistente;

ícones adequados;

espaçamento correto;

estados hover;

estado active;

estado disabled.

Não alterar as ações executadas pelos botões.

10. MODAIS

Melhorar visualmente todos os modais existentes.

Utilizar:

cabeçalho claro;

título;

descrição quando existente;

conteúdo bem espaçado;

rodapé com ações;

botão de fechar consistente;

largura adequada;

backdrop discreto.

Os modais devem funcionar exatamente como atualmente.

Não modificar a lógica de abertura, fechamento ou salvamento.

11. CADASTROS

Melhorar a apresentação visual das telas de cadastro.

Especial atenção para:

categorias;

subcategorias;

clientes;

fornecedores;

contas;

centros de custo;

formas de pagamento;

demais cadastros existentes.

A relação visual entre:

Categoria → Subcategoria

deve ser extremamente clara.

Utilizar indentação, agrupamento e hierarquia visual adequados.

Não modificar a estrutura ou funcionamento dos cadastros.

12. LANÇAMENTOS FINANCEIROS

Melhorar a experiência visual dos lançamentos.

A interface deve facilitar a identificação de:

receitas;

despesas;

transferências;

datas;

vencimentos;

valores;

contas;

categorias;

subcategorias;

centros de custo;

status;

informações fiscais/contábeis já existentes.

Não alterar nenhuma regra financeira ou fiscal.

13. GRÁFICOS

Melhorar visualmente os gráficos existentes.

Priorizar:

legibilidade;

títulos claros;

legendas organizadas;

eixos discretos;

valores fáceis de interpretar;

tooltips elegantes;

espaçamento adequado.

Não alterar:

fonte dos dados;

cálculos;

filtros;

períodos;

métricas.

Apenas melhorar a apresentação.

14. CORES

Utilizar uma paleta profissional e discreta.

As cores devem ter função semântica.

Por exemplo:

receita → identificação positiva;

despesa → identificação negativa;

pendência → atenção;

sucesso → confirmação;

erro → alerta;

informação → neutro.

Não utilizar cores apenas como decoração.

Manter contraste adequado e boa acessibilidade.

15. ÍCONES

Padronizar os ícones existentes.

O sistema já utiliza ícones Lucide localmente.

Preserve essa abordagem e não introduza bibliotecas externas desnecessárias.

Os ícones devem:

possuir tamanhos consistentes;

estar visualmente alinhados;

representar corretamente suas ações;

não competir visualmente com os textos.

16. ESPAÇAMENTO E GRID

Criar uma estrutura de espaçamento consistente.

Evitar:

elementos colados;

espaços excessivos;

desalinhamentos;

cards com alturas inconsistentes;

botões desalinhados;

títulos fora da grade.

Utilizar uma grid visual consistente em toda a aplicação.

17. RESPONSIVIDADE

Melhorar a responsividade sem alterar funcionalidades.

Desktop:

aproveitar adequadamente o espaço disponível;

manter boa densidade de informação.

Tablet:

reorganizar colunas quando necessário.

Mobile:

empilhar elementos;

permitir rolagem horizontal em tabelas quando necessário;

manter botões acessíveis;

evitar textos cortados;

evitar elementos ultrapassando a tela.

Não esconder funcionalidades simplesmente para resolver problemas de responsividade.

18. MICROINTERAÇÕES

Adicionar apenas microinterações discretas quando forem úteis:

hover;

focus;

transições suaves;

abertura de modal;

feedback visual de seleção;

estados de carregamento já existentes.

Não criar animações exageradas.

A interface deve parecer rápida e profissional.

19. ACESSIBILIDADE

Melhorar:

contraste;

foco de teclado;

tamanho de áreas clicáveis;

labels;

estados de foco;

leitura dos textos;

diferenciação de estados.

Não utilizar apenas cor para transmitir uma informação importante.

23. CRITÉRIO DE ACEITAÇÃO

A alteração será considerada concluída somente se:

A interface estiver visualmente mais profissional.

A navegação estiver mais clara.

Os elementos estiverem melhor organizados.

A hierarquia visual estiver melhor.

A experiência de uso estiver mais confortável.

A responsividade estiver melhor.

O sistema continuar executando as mesmas funções.

Nenhum cálculo tiver sido alterado.

Nenhum dado existente tiver sido perdido.

Nenhuma funcionalidade tiver sido removida.

Nenhuma regra de negócio tiver sido modificada.
